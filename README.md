# Траты по лимитам

Семейный бюджет на двоих: ввод трат и доходов, семейные и личные лимиты, общие копилки, график по месяцам.
Next.js 16 (App Router) + Postgres (Neon, Drizzle), вход по email и паролю (Better Auth).

## Модель

- **Семейные траты** — общие категории и лимиты, видят оба.
- **Личные траты** — свои категории и лимиты, видит только автор. Партнёру сервер отдаёт только суммы за месяц и по дням.
- **Доходы** записываются на автора и видны обоим.
- **Сбережения** — счета (семейные и личные) с ручной сверкой остатков и копилки как распределение общей суммы.
  Копилка ведётся в своей валюте. Личные счета и копилки партнёру видны только суммой.
- **План месяца** — ожидаемый доход, лимиты только на этот месяц и плановые покупки. Трата по пункту плана
  не входит в шкалу категории, кроме превышения суммы пункта. Личное партнёра в плане — только суммами.

## Как хранятся данные

| Ключ | Тип | Что |
|---|---|---|
| `ft:settings` | JSON | семейные настройки + `version` |
| `ft:goals` | JSON | старые копилки — резервная копия после переноса в «Сбережения» |
| `ft:accounts` | HASH | семейные счета: поле = id, у каждого свой `version` |
| `ft:u:<id>:accounts` | HASH | личные счета пользователя |
| `ft:goals2` | HASH | семейные копилки |
| `ft:u:<id>:goals` | HASH | личные копилки |
| `ft:recons` | ZSET | снимки сверок, score = время; поштучные остатки только на сервере |
| `ft:plan:2026-11` | JSON | семейная часть плана: ожидаемый доход, поправки семейных лимитов + `version` |
| `ft:u:<id>:plan:2026-11` | JSON | личные поправки лимитов на месяц + `version` |
| `ft:plan-items:2026-11` | HASH | семейные плановые покупки |
| `ft:u:<id>:plan-items:2026-11` | HASH | личные плановые покупки |
| `ft:m:2026-10` | HASH | семейные траты месяца: поле = id записи |
| `ft:i:2026-10` | HASH | доходы месяца обоих |
| `ft:u:<id>:settings` | JSON | личные категории пользователя + `version` |
| `ft:u:<id>:m:2026-10` | HASH | личные траты пользователя |
| `ft:index` | SET | ключи месяцев и планов, чтобы не использовать SCAN |
| `ft:push` | HASH | push-подписки устройств: поле = endpoint, значение = { userId, subscription } |
| `ft:push:version` | строка | коммит, о котором уже сообщили пушем |
| `ft:trash:<id>` | JSON, TTL 10 мин | удалённая запись для «Вернуть» |
| `ft:u:<id>:tokens` | HASH | токены Быстрых команд: поле = id, значение = { name, hash (SHA-256), createdAt, lastUsedAt } |
| `ft:quick-rate:<tokenId>:<минута>` | счётчик, TTL 60 с | лимит 30 запросов в минуту на токен |
| `ft:doc:*`, `ft:docs` | JSON | старый формат одного пользователя — резервная копия после миграции |

Записи — поля хешей, поэтому добавление и удаление атомарны и двое не перетирают друг друга.
Настройки и личные настройки пишутся целиком с проверкой версии (Lua через `EVAL`): при расхождении — 409.
Счета и копилки — по одной записи хеша с тем же CAS; сверка проверяет версии всех счетов и пишет остатки и снимок одним скриптом.

API:

- `GET /api/data` — всё, что видно текущему пользователю
- `POST /api/entries`, `DELETE /api/entries/:id?kind=&scope=&month=`, `POST /api/entries/restore` — записи
- `PUT /api/settings`, `PUT /api/my-settings` — `{ version, data }`, 409 при конфликте
- `POST /api/accounts`, `PATCH /api/accounts/:id` — счета; `POST /api/reconcile` — сверка остатков и снимок
- `POST /api/goals`, `PATCH|DELETE /api/goals/:id`, `POST /api/goals/:id/ops` — копилки
- `GET /api/plan?month=`, `PUT /api/plan/:month`, `PUT /api/my-plan/:month` — план месяца, 409 при конфликте
- `POST /api/plan-items`, `PATCH|DELETE /api/plan-items/:id` — покупки; `POST /api/entries` принимает `planItemId`
- `GET|POST|DELETE /api/push`, `POST /api/push/test` — подписка устройства и тестовый пуш
- `POST /api/quick` — `{ text, commit }` для Siri, доступ по `Authorization: Bearer <токен>` (без cookie); `GET|POST|DELETE /api/quick/tokens` — мои токены
- `GET /api/cron/daily` — напоминания (Vercel Cron, `Authorization: Bearer CRON_SECRET`)
- `PATCH /api/settings/rates` — слияние курсов без 409
- `POST /api/rebase` — смена базовой валюты, пересчитывает данные обоих одной транзакцией
- `GET /api/rates` — курсы ExchangeRate-API
- `/api/auth/*` — Better Auth: `sign-in/email`, `sign-out`, `get-session`, `list-sessions`, `revoke-session`,
  `revoke-other-sessions`, `change-password`, `update-user`. Регистрация отключена

Вход: Better Auth (`lib/auth.ts`), пользователи и сессии в Postgres; пользователь Better Auth — строка таблицы
`users`, его id и есть id в данных. `proxy.ts` только проверяет наличие cookie сессии, полная проверка и бюджет
пользователя (`memberships`) — в каждом обработчике (`requireUser`). Попытки входа ограничены: 5 в минуту с IP,
счётчики в базе. Сессия живёт год и продлевается при использовании.

### Регистрация, семья, архив

- Регистрация: email, пароль (от 10 символов), имя; email подтверждается письмом, до этого входа нет. В режиме
  `invite` нужен код закрытой беты (создаёт админ: Настройки → Бета, ссылка `/signup?code=…`) или ссылка-приглашение в семью.
- Первый вход — бюджет одного человека (solo): всё личное, интерфейс без семейных частей (флаг `isSolo`).
- Настройки → Семья → «Пригласить»: ссылка `/join/<код>`, одноразовая, 7 дней. Принятие переносит данные приглашённого
  в семью личными (доходы до вступления не переносятся), при разных валютах — пересчёт по курсу. В семье до 6 человек.
- Выход (`/leave`, слово ВЫЙТИ): если остаётся один — семья распускается в архив на 90 дней, у каждого свой solo с его
  личными данными; иначе семья живёт, у ушедшего архив до даты выхода. Разбор (`/review/<id>`): забрать счёт, продолжить
  платёж, копия копилки, категории. Восстановление — когда согласятся все участники роспуска. Cron удаляет архивы после `purge_at`.
- Настройки → Аккаунт: экспорт всех своих данных (JSON), удаление аккаунта (пароль + слово УДАЛИТЬ). `/privacy` — черновик.
- Смоук по HTTP на сборке и пустой локальной базе: `npm run build && DATABASE_URL=… npm run smoke`.

### Пользователи и пароли

Прежние пользователи переносятся скриптом. Для пользователя, уже перенесённого в `users`:

```sh
MIGRATE_USERS="vlad:vlad@example.com,masha:masha@example.com" PASSWORD_VLAD=… PASSWORD_MASHA=… \
  npm run db:migrate-users -- --dry-run      # затем без --dry-run
```

Повторный запуск безопасен и уже заданный пароль не меняет. Пароль меняется в «Настройках → Аккаунт»
(минимум 10 символов, другие устройства выходят).

**Забытый пароль** (писем пока нет). С переменными подключения к базе, как для `db:migrate`
(production-база — с `PRODUCTION_DB_HOST` и `--production`):

```sh
npm run reset-password -- masha@example.com --production
```

Скрипт выводит временный пароль и завершает все сессии пользователя. Передайте пароль лично; после входа
его стоит сменить в «Настройках → Аккаунт». Обычный путь — «Забыли пароль» на странице входа (письмо со ссылкой);
скрипт — запасной, если письма не доходят.

## Деплой на Vercel

1. Залейте проект в GitHub и импортируйте репозиторий в Vercel (New Project). Настройки сборки по умолчанию.
2. В проекте на Vercel: **Storage → Create Database → Upstash for Redis** (Marketplace), бесплатный план,
   подключите к проекту. Переменные `KV_REST_API_URL` и `KV_REST_API_TOKEN` появятся сами.
3. **Settings → Environment Variables**, добавьте:
   - `DATABASE_URL`, `DATABASE_URL_UNPOOLED` — Postgres (появятся сами при подключении Neon через Storage);
   - `BETTER_AUTH_SECRET` — длинная случайная строка (`openssl rand -hex 32`);
   - `BETTER_AUTH_URL` — адрес production, например `https://spendlog.vercel.app` (на preview адрес берётся из
     системных переменных Vercel);
   - письма (подтверждение email, сброс пароля, «пароль изменён», «аккаунт удалён») — по SMTP или через Resend:
     - SMTP: `SMTP_HOST`, `SMTP_PORT` (465 — TLS, 587 — STARTTLS), `SMTP_USER`, `SMTP_PASS`. Для Gmail:
       `smtp.gmail.com`, 465, ваш адрес Gmail и пароль приложения (Google Аккаунт → Безопасность → двухэтапная
       аутентификация → Пароли приложений). Лимит Gmail — около 500 писем в день;
     - Resend: `RESEND_API_KEY`; без подтверждённого домена письма уходят только владельцу аккаунта Resend;
     - `MAIL_FROM` — отправитель, по умолчанию для SMTP — `SMTP_USER`. Заданы оба способа — используется SMTP;
   - `TURNSTILE_SITE_KEY`, `TURNSTILE_SECRET_KEY` — Cloudflare Turnstile на регистрации и сбросе пароля
     (в настройках виджета добавьте домен приложения). Без них капчи нет;
   - `REGISTRATION_MODE` — `invite` (по умолчанию: регистрация по коду или ссылке-приглашению) или `open`;
   - `ADMIN_USER_IDS` — id админов через запятую: у них в настройках раздел «Бета» с кодами регистрации.
4. Сделайте Redeploy, чтобы переменные подхватились. Без `DATABASE_URL` и `BETTER_AUTH_SECRET` сервер не стартует.
5. Схема — `npm run db:migrate`, пользователи — `npm run db:migrate-users` (раздел «Пользователи и пароли»).

На телефоне удобно добавить сайт на главный экран: в Safari «Поделиться → На экран „Домой“».

### PWA, офлайн и уведомления

- Приложение устанавливается на главный экран (манифест `app/manifest.ts`, иконки в `app/` и `public/`).
- Без связи открывается последняя копия данных (`public/sw.js`). Можно только записывать траты и доходы — они ждут
  в очереди и уходят при появлении сети. Удаление, настройки, план и сверка без связи недоступны.
- Push-уведомления: «приложение обновилось» (первый старт нового коммита в production), план на следующий месяц
  за 2 дня до конца (если плана ещё нет), по воскресеньям — внести траты. Включаются в «Настройках» на каждом
  устройстве; на iPhone — только у приложения, открытого с экрана «Домой» (iOS 16.4+).
- Для уведомлений задайте `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` (`npx web-push generate-vapid-keys`),
  `VAPID_SUBJECT` и `CRON_SECRET`. Расписание — `vercel.json`, раз в день в 17:00 UTC (19:00 летом / 18:00 зимой по Белграду).
  Для пуша об обновлении в настройках проекта Vercel должны быть включены системные переменные (включены по умолчанию).

## Голосовой ввод

Строка над переключателем «Расход / Доход»: нажмите «● Голос» и скажите траты одной фразой — или напечатайте их.
Перед записью всегда видно, как фраза понята, без проверки ничего не записывается.

### Как говорить

- Одна трата: «кофе 350», «такси 800», «2к лидл».
- Несколько сразу — через «и», запятую, «плюс», «ещё»: «кофе 350 и такси 800».
- Сумма цифрами или словами: «тысяча двести», «полторы тысячи», «1,5к», «2 тыс».
- Валюта — рядом с суммой: «45 евро», «20 долларов». Без валюты — основная.
- Дата: «вчера», «позавчера», «в пятницу», «12-го», «12 октября». Без даты — сегодня.
- Чья трата: «себе», «лично» — личная; «семья», «общее», «в дом» — семейная. Без этого слова — по категории или как в прошлый раз.
- Категория — по названию («продукты»), по словам из ваших прошлых заметок и по типичным словам: кофе → кафе, такси → транспорт, лидл → продукты, аптека → здоровье.
- Остальные слова становятся заметкой. Чем чаще вы пишете заметки, тем точнее угадывается категория.

Доходы, регулярные платежи и плановые покупки голосом не вводятся — для них обычная форма.

### Проверка перед записью

- `? КАФЕ` жёлтым — категория угадана неуверенно: выберите из подсказок или «Другая». Записать можно и так.
- `!! НЕТ СУММЫ`, `!! ВАЛЮТА … НЕ ПОДКЛЮЧЕНА` — такую трату не записать: поправьте фразу или уберите строку кнопкой ×.
- Нажмите на строку — трата перейдёт в обычную форму для ручной правки.
- «Записать» или Enter — записываются все строки сразу. В уведомлении «Отменить» удаляет всё, что записано этим нажатием.

### Если микрофон не работает

- Нет кнопки распознавания в браузере (бывает на iPhone в приложении с экрана «Домой») — нажмите 🎤 на клавиатуре и продиктуйте в строку: результат тот же.
- «Нет доступа к микрофону» — разрешите микрофон для сайта в настройках браузера.
- На компьютере: `/` — перейти в строку, `Alt + M` — включить и выключить микрофон.

Не нужна строка — **Настройки → Голосовой ввод → Скрыть** (только у вас, на всех ваших устройствах; Siri продолжает работать).

Без открытия приложения — через Siri, см. ниже.

## Siri

Траты голосом без открытия приложения: «Привет, Siri, трата» → «кофе 350 и такси 800» → Siri переспрашивает → «Записать».
Фраза разбирается так же, как в строке голосового ввода на странице ввода. Доходы, регулярные и плановые траты голосом не вводятся.

### 1. Токен

В приложении: **Настройки → Быстрые команды**, впишите имя устройства и нажмите «Создать токен».
Токен показывается один раз — скопируйте его. Токен даёт доступ только к записи трат через `/api/quick`,
траты записываются от вашего имени. Потерянный токен отзовите там же.

### 2. Быстрая команда

На iPhone откройте приложение «Быстрые команды» → «+» и добавьте действия по порядку:

1. **Диктовать текст** — язык: «Русский», «Прекратить слушать»: «После паузы».
2. **Получить содержимое URL** — URL: `https://<ваш-домен>/api/quick`. Раскройте «Показать больше»: метод `POST`; заголовки — `Authorization` со значением `Bearer <токен>`; текст запроса — `JSON` с полями: `text` (Текст) = переменная «Продиктованный текст», `commit` (Логическое значение) = выкл.
3. **Получить значение словаря** — значение для ключа `summary` в «Содержимое URL».
4. **Выбрать из меню** — вопрос: переменная «Значение словаря»; пункты `Записать` и `Отмена`.
5. В пункт `Записать` перетащите: **Получить содержимое URL** — тот же URL, метод, заголовок и JSON, но `commit` = вкл.; затем **Получить значение словаря** `summary`; затем **Озвучить текст** — «Значение словаря».
6. Пункт `Отмена` оставьте пустым.

Если Siri не поняла сумму или категорию, вопрос сразу это скажет (`Не понял сумму в «такси»`) — выберите «Отмена» и повторите.
При «Записать» сервер разбирает фразу заново и ничего не пишет, если в ней ошибка.

### 3. Название

Нажмите на название команды сверху и переименуйте её в «Трата». Теперь её вызывает фраза «Привет, Siri, трата».
Команду можно добавить и на экран «Домой» или в виджет.

Ограничение: не больше 30 запросов в минуту на токен.

## Структура

```
app/
  (app)/            страницы за авторизацией: / (ввод), /limits, /savings, /chart, /settings
  api/              auth (Better Auth), data, entries, settings, my-settings, accounts, reconcile, goals, rebase, rates, …
  login/            страница входа
components/         TrackerProvider (состояние, оптимистичные записи, опрос раз в минуту), экраны
lib/                типы, утилиты, data (репозитории Postgres), auth (вход), сборка ответа (store), пересчёт валют, миграция, метрики
proxy.ts            есть ли cookie сессии (иначе /login)
instrumentation.ts  проверка переменных окружения при старте
```
